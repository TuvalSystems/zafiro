v0.4.8: (Dennis Betancourt - 07/Oct/2019)
------
Al armar el XML de Factura, Guia de remision y Nota de credito, en la etiqueta <codigoAuxiliar> se puso la funcion reemplazarCaracter() para que se reemplace algun caracter especial que se encuentre en dicho campo. Casos: Si se encuentra '&' se colocara '&amp;'. Si se encuentra '<' se colocara '&lt;'. Si se encuentra '>' se colocara '&gt;'.

v0.4.9: (Dennis Betancourt - 17/Oct/2019)
------
Al armar el XML de Factura, Nota de credito y Retencion, en la etiqueta <campoAdicional> se puso una validacion para que, en caso que el valor del campo sea mayor a 300 caracteres, se trunque y solo se tomara en cuenta 300 caracteres.

v0.4.10: (Dennis Betancourt - 12/Dic/2019)
-------
Al armar el XML de Retencion, se cambio el nombre de campo y tabla donde se obtiene la fecha_emision_factura_proveedor. Antes se lo obtenia de tbm_pagMovInv.fe_recChq. Ahora se lo obtiene de tbm_detRecDoc.fe_venChq.

v0.4.11: (Dennis Betancourt - 03/Ene/2020)
-------
Se realizaron cambios debido a que Cosenco fue anexada a la base de datos Zafiro2006.

v0.4.12: (Dennis Betancourt - 17/Ene/2020)
-------
En la clase ZafFirma_p12, en el metodo getFirstCertificate() se cambio la manera de firmar los XML, debido a un cambio en el SRI que ellos lanzaron el 15/01/2020.
Antes: X509Certificate certificate = certs.get(0); //Firma usando "cifrado de clave"
Ahora: X509Certificate certificate = certs.get(1); //Firma usando "firma digital"

v0.4.13: (Dennis Betancourt - 22/Ene/2020)
-------
Al armar el XML de Retencion, en el query que trae el detalle se agrego la condicion "and a7.st_reg = 'A'" donde a7 = tbm_detRecDoc. Se puso esta condicion debido a que en el XML se duplicaban los valores de las bases imponibles y retenciones si existe una Recepcion de factura de proveedor anulada. Caso presentado en Tuval California, Retencion 42266 Proveedor "SANCHEZ RIVAS CESAR AUGUSTO".

v0.4.14: (Dennis Betancourt - 06/Feb/2020)
-------
1) Al armar el XML de Retencion, en el query que trae el detalle se agrego la condicion "and a2.tx_numChq = a7.tx_numChq", donde el campo tx_numChq tiene el num.Fac.Prv. en las tablas tbm_pagMovInv (alias a2) y tbm_detRecDoc (alias a7). Se puso esta condicion debido a que en el XML se estaba generando 2 filas para un mismo porcentaje_Retencion. Ej: habian 2 filas para 1%, y 2 filas para 10%. Caso presentado en Castek Quito Inmaconsa, Retencion 5 y 6, Proveedor "DIPAC MANTA".
2) Se creo la funcion getSQLSubRepCpbRet_XML(), el cual ya no va a traer la informacion de la base de datos. Ahora se leera los datos de los valores de Base Imponible y de Retencion basado en el XML autorizado.

v0.4.15: (Dennis Betancourt - 11/Feb/2020)
-------
Se agrego la funcion verificar_DetXML_DetPag_Ret() la cual se encarga de verificar que los datos del XML de Retencion que se va a armar sean iguales a los que estan en tbm_detPag.

v0.4.16: (Dennis Betancourt - 11/Mar/2020)
-------
En la funcion verificar_DetXML_DetPag_Ret(), se verifica si hay FACCOM que estan relacionadas con la Retencion. Si hay mas de una FACCOM, no se debe continuar con el proceso de validacion. Sin embargo, se devuelve true para indicar que el proceso de validacion estuvo OK. Caso presentado en Tuval Inmaconsa, Num_ret 2585, Proveedor 1004 = DEMACO, fe_emision 09/03/2020.
